# Proposal

## Why

ERP 用户需要在当前业务页面直接表达需求、获得可核实的回答并继续完成业务操作，固定格式指令与脱离页面的聊天会打断工作。项目尚未建立应用基础，需要以采购订单场景建立可持续迭代的嵌入式助手，并从首版覆盖身份、草稿、确认、执行和恢复。

## What Changes

- 面向使用 jshERP 的采购人员与有相应权限的业务用户，提供全局侧边栏；支持收起、恢复、展开任务详情以及当前页面与选中记录上下文。
- 以聊天为主界面：顶部新建/历史会话入口、单一消息滚动区和底部固定输入框；页面上下文与任务按需展开，采购卡片随消息展示。
- 复用 ERP 当前登录身份，在服务端验证用户、租户、仓库和操作权限；任务与历史记录按用户及 ERP 连接隔离。
- 主 Agent 统一承接自由表达、普通交流、只读业务查询与多轮任务；复杂采购准备按需委派采购专业 Agent，简单查询直接调用工具。
- 通过真实 ERP API 查询已有商品、商品单位、供应商和授权仓库库存；区分空数据、无权限、认证失效和依赖失败。
- 以结构化卡片编辑采购订单草稿，支持表单和自然语言修改、多商品选择、缺项澄清、版本冲突与取消。
- 用户明确确认指定草稿后，受控服务创建 **未审核采购订单**，核对真实 ERP 单号与明细；采购订单不执行入库、付款或自动审核。
- 保存会话、任务、草稿和执行记录，支持断线与重启后的恢复、重复提交防护、超时结果核对、必要的人工处理和脱敏观测。
- 分三段实现和验收：嵌入与会话基础 → 对话与只读 ERP 查询 → 采购草稿与可靠执行；最终按完整闭环验证后归档。

### Scope Boundaries

首版采购使用已有商品与供应商，以人民币、无订金、无额外费用、无折扣且零税率的普通采购订单为初始支持范围；支持 ERP 已配置的有效单位，金额与换算由服务校验。超出范围时说明限制并提供 ERP 手工处理入口，不静默丢弃条件。

不包括采购入库、付款、ERP 审核、修改或删除既有 ERP 单据、自动新建主数据、定时自主采购、通用 Agent 平台、任意 SQL/代码执行、全 ERP 页面深度接入或跨域嵌入。首批页面适配为商品列表与采购订单列表；其他页面保留通用助手与明确的上下文可用状态。

### Decisions And Assumptions

- 已确定：FastAPI、React/Vite、shadcn/ui/Tailwind、TanStack、开源持续迭代、主 Agent 与专业 Agent 配合受控业务流程。
- 本提案建议：同源部署的 iframe 侧边栏、当前 ERP 用户会话接入、PostgreSQL 保存助手状态、LangGraph 承载有界的对话编排；具体取舍见 design。
- 源码证据：检查了 Talk2Stock 内包含的 jshERP 快照，存在全局布局、会话验证、商品/库存查询、采购订单创建与按单号核对入口；采购订单明细不需要仓库。源码检查不等于真实接口验收，也不代表所有 jshERP 发行版本兼容。
- 实施前必须完成版本化接口契约验证，尤其是权限与价格可见性、商品 ID/扩展 ID、金额符号、创建结果核对。无法验证时保持相关操作不可用，不能回退为管理员代办。

## Capabilities

### New Capabilities

- `embedded-assistant`：ERP 侧边栏、宿主桥接、页面上下文和有限宿主动作。
- `erp-access`：ERP 身份接入、数据与操作权限、只读查询及适配错误语义。
- `conversation-orchestration`：连续对话、主/专业 Agent 契约、有界调用和统一回复。
- `purchase-drafts`：采购意图、实体与单位解析、可编辑草稿卡片和明确确认。
- `purchase-execution`：未审核采购订单写入、幂等、回执核对与未知结果恢复。
- `task-lifecycle`：持久化、任务切换、事件恢复、失败处理、观测与验收记录。

### Modified Capabilities

无；当前主规范为空。

## Impact

新增 `backend/`、`frontend/` 与 `integrations/jsh-erp/` 等应用和接入内容，以及部署、配置、接口契约、场景评估和 CI 文档。助手 API 初步使用 `/assistant/api/v1/`，与 ERP 现有 API 分开。

jshERP 宿主需要可移除的入口、桥接和首批页面适配；项目内维护补丁/接入说明，并内置固定提交的 jshERP 所需源码、许可证、公开结构及菜单，提供独立本地开发栈；不依赖贡献者的其他项目、已构建私有镜像或本机源码位置。上游业务数据和凭据不随源码导入。ERP 数据仍由其业务 API 管理，助手数据库不直接操作 ERP 表。

新增 PostgreSQL、Agent 运行时与模型连接配置；模型供应商可配置，不强制云平台或付费观测服务。基础依赖在实现时锁定并记录许可与来源；项目许可证仍由维护者确定。当前没有已发布 API 或数据，首次引入不构成既有用户迁移；后续协议和数据库变更需版本与迁移管理。
