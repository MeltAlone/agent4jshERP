本轮模型自主选择直接工具，委派次数均为零；不能据此声称真实专业 Agent 协作已验收。专业建议结构、禁止递归委派和主 Agent 汇总由测试替身验证，真实委派场景仍待补测。

复现前先启动隔离 ERP 并完成虚构数据准备，配置有效模型连接：

```sh
uv run --project backend python scripts/evaluate_readonly.py
# 也可以只运行指定场景
uv run --project backend python scripts/evaluate_readonly.py --scenario stock
```

该脚本只允许默认隔离验证 ERP 地址，读取忽略目录中的虚构账号凭据，执行只读工具，不调用采购执行接口。
所有 Agent 共用调用预算；业务调用在执行前持久化预留，检查点恢复不会刷新次数预算。
价格权限变化后以当前权限过滤历史，检查点线程包含 owner 与权限指纹，禁止恢复旧权限下的数据。

当前限制：仍需完成采购草稿真实浏览器验收、真实委派及完整采购执行/故障闭环；实施进度见 OpenSpec 任务清单。

## 模型响应格式故障

模型 HTTP 请求成功并不代表对话决策有效。连接器校验响应外层、截断标记、非空文本、JSON 和决策字段；格式不合要求时返回 `model_invalid_response`，不执行该响应中的工具或草稿动作。系统最多追加一次连续失败重试，格式错误时使用固定纠正提示，仍占用主/专业 Agent 共享模型次数与时长预算。预算不足时直接停止。

失败 trace 只记录固定 `reason` 分类：`invalid_envelope`、`empty_content`、`truncated_output`、`invalid_json`、`invalid_decision`、`response_too_large`。不保存供应商响应原文或 Pydantic 校验输入。旧运行没有分类时，只能确认校验失败，不能据此判断具体缺失字段或截断原因。

界面区分模型格式错误、服务不可用、超时和预算耗尽。只有确有查询事实时才提示保留查询结果；无事实时不声称已经查询，也不将模型故障归因于用户缺少信息。重新发送需求会建立新运行；已保存的历史失败消息不会被改写。
