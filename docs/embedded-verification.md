# 嵌入与页面任务验证

日期：2026-11-12。环境为本地独立 `a4j-contract` ERP、`agent4jsherp` PostgreSQL/代理、真实浏览器；业务数据均为公开生成的虚构夹具。兼容来源见 [ERP 实测记录](integrations/jsh-erp-verification-v1.md)，会话部署见 [身份文档](integrations/assistant-session-v1.md)。

## 浏览器实测

| 场景 | 实际结果 |
| --- | --- |
| 多页签布局切商品、首页、采购订单 | 一个 GlobalLayout 入口，iframe nonce 不变；当前身份与已保存任务保留 |
| 普通布局 | 在被忽略的验证副本把 main.js 的 SET_MULTI_PAGE 初始化临时固定 false，重建后确认无 tablist；打开助手、恢复三个本人任务、切首页，iframe src/nonce 保持一致；验收后还原原文件并重建 |
| 选中 330ml 可乐保存任务，改选矿泉水 | 改选后任务仍为可乐版本 1；显式采用才成为矿泉水版本 2 |
| 再建可乐任务并来回切换 | 两个任务分别保留可乐版本 1 和矿泉水版本 2，没有覆盖 |
| 从商品页切走再返回 | 页面选择清空，保存任务不变；首页显示上下文不可用 |
| 采购订单选择并保存 | 服务端重新核对授权列表后保存 CGDD00000001002；“查看订单”打开 ERP 真实只读详情 |
| 刷新当前 ERP 列表 | 仅调用当前采购列表适配器；订单仍可见，未发起创建 |
| 侧栏调宽/展开 | 默认 420px；键盘 ArrowLeft 后 440px，详情展开 900px，恢复 440px |
| 窄视口 | 580px 宽时面板占满视口；桌面 1280px 下保持侧栏 |
| iframe 内 Escape | 侧栏收起，焦点返回“业务助手”入口，重新打开保留任务 |
| 双标签页 buyer → masked → buyer | 原页收到切换清理；masked 无 buyer 任务且采购新增关闭；buyer 再登录恢复原任务 |

打开订单使用上一阶段通过正常 ERP 界面创建的虚构订单，未在本阶段创建额外 ERP 单据。这里的任务为页面上下文任务；尚未生成采购草稿，也未验证不存在的 Agent 对话 UI。3.5 的完整消息/草稿/事件切换场景继续保留待验收。

## 自动验证

- 后端 50 项测试通过，包含 PostgreSQL 独立 schema、跨 owner、消息去重、worker 进程恢复、SSE 游标与重放、身份切换、撤销价格过滤、上下文命令/版本/新鲜度、列表分页不完整拒绝及订单定位。
- 前端 9 项测试通过，覆盖 bridge 来源/窗口/nonce/版本/schema/大小与动作白名单、选择时间、事件去重和旧身份晚到响应丢弃。
- 夹具 4 项保护测试通过；Ruff 检查及格式检查通过；前端类型和生产构建通过；OpenSpec strict 校验通过。
- 后端 TestClient 发出上游 httpx 兼容弃用警告，当前测试通过；未将弃用警告当作接口兼容承诺。

自动替身拒绝用例不能替代真实 ERP；真实身份验证另执行 `scripts/verify_identity.py`，正常订单只读核对执行 `integrations/jsh-erp/verification/verify_order.py --number <fixture 单号>`。这些验证不会把模拟事件当成业务成功。

## 复现顺序

按 [开发指南](development.md) 启动并迁移数据库；按 [宿主文档](../integrations/jsh-erp/host/README.md) 安装、构建、挂载隔离副本。先验证 buyer 登录及任务保存，再验证页面/任务独立、订单定位、视口与键盘操作，最后用两个标签页切换到受限身份并返回。刷新旧页签后才恢复；不要把浏览器保存的其他 ERP 登录状态混入验证。

补丁 apply/remove 已在验证副本往返执行；安装器拒绝未知原文件和安装后额外修改。生产 TLS、正式静态发布及完整业务闭环仍须对应阶段验收。
